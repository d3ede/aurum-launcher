# Вход с Microsoft в Aurum

Пользователь нажимает «Войти с Microsoft». Aurum открывает настоящую страницу Microsoft в отдельном окне WebView2, принадлежащем лаунчеру. После выбора аккаунта и подтверждения доступа окно закрывается, а Aurum завершает вход автоматически. Вкладка в системном браузере не открывается. Вводить код, токен или Client ID не нужно. Пароль и двухфакторная проверка остаются на стороне Microsoft.

Диалог Aurum показывает подготовку, ожидание подтверждения, подключение Minecraft Java и результат. Доступны возврат к окну Microsoft, отмена, повторная попытка и переход к сборкам. Закрытие окна Microsoft отменяет текущий вход. Светлая и тёмная темы используют общий узор `TerrainPattern` с главной страницы.

## Однократная настройка разработчиком

1. Откройте [Microsoft Entra](https://entra.microsoft.com/). Перейдите в **Entra ID → App registrations → New registration**.
2. Название: **Aurum Launcher**. Supported account types: **Personal Microsoft accounts only**. Также подходит вариант, включающий организационные и личные Microsoft-аккаунты; сам лаунчер использует endpoint `consumers`.
3. Нажмите **Register**. В **Overview** скопируйте **Application (client) ID**.
4. Откройте **Authentication → Add a platform → Mobile and desktop applications**. Добавьте **`http://localhost`** и сохраните. Не выбирайте Web или SPA. Секрет приложения не нужен.
5. Укажите публичный ID в `config/microsoft-client-id.txt` и пересоберите лаунчер. В этой реализации уже указан предоставленный владельцем проекта ID `5800f49c-6f6b-4808-9c89-dabd305c8dd8`.

Для отдельной сборки ID можно переопределить переменной окружения во время компиляции:

```powershell
$env:AURUM_MICROSOFT_CLIENT_ID = 'идентификатор-вашего-приложения'
./scripts/desktop.ps1 -Mode build
```

Client ID публичный, его можно хранить в исходниках. Client secret, пароль аккаунта и токены в этот файл не помещают.

Источники: [регистрация приложения Microsoft](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app), [Authorization Code с PKCE](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow), [правила адресов возврата localhost](https://learn.microsoft.com/en-us/entra/identity-platform/reply-url#localhost-exceptions).

## Доступ к Minecraft и проверка настоящего аккаунта

Регистрация в Entra и наличие Client ID сами по себе не подтверждают доступ к Minecraft Services. Проверяйте последовательно: выбор аккаунта Microsoft, разрешение входа, обмен токенов Xbox/XSTS, доступ к Minecraft Services и получение профиля Java. Если Minecraft Services возвращает 403, разработчику нужно уточнить доступ приложения у поддержки Minecraft. Старые ссылки на заявку доступа не удалось подтвердить; здесь не обещается, что такая заявка сейчас доступна.

Для проверки используйте аккаунт с Minecraft Java и Xbox-профилем. Если приложение на странице Microsoft отклонено до возврата, проверьте тип личных аккаунтов и native redirect `http://localhost`. Токены, коды авторизации и пароли не публикуйте в отчётах. Старые сессии, созданные с другим ID до этого обновления, могут потребовать повторного входа.

## Реализация и границы проверки

OAuth Authorization Code с PKCE S256 и случайным `state`. Временный обработчик слушает только IPv4 loopback на свободном порту; Microsoft допускает разные порты для зарегистрированного `http://localhost`. Он проверяет путь, состояние сессии и неоднозначные параметры. Ожидание ограничено десятью минутами; отмена прерывает ожидание и сетевые запросы. Произвольные запросы и ответы других сессий не завершают вход.

Код и PKCE verifier не передаются в интерфейс и не выводятся в события. Токены обновляются автоматически и сохраняются в хранилище учётных данных ОС вместе с ID приложения, выдавшего сессию. После валидного ответа Microsoft окно закрывается, и результат показывается в главном окне Aurum. Окно Microsoft использует отдельный профиль WebView2 и не имеет доступа к IPC-командам лаунчера. Существующий native redirect http://localhost сохраняется; повторная настройка Entra не требуется.

Автоматические проверки используют локальный HTTP callback и имитацию IPC в интерфейсе: подтверждение, отказ, отмена, повторная попытка, ошибка открытия браузера и обе темы. Это не подтверждает вход в Microsoft или доступ нового Client ID к Minecraft Services: такой результат требует реального аккаунта и настроенного приложения.


Проверка настоящего WebView2 без ввода учётных данных: `scripts/native-microsoft-smoke.mjs`. Диагностический бинарник собирают с отдельным идентификатором `app.auren.launcher.auth-smoke`, а скрипт использует только свою новую папку `.test-data/`. Подтверждены создание owned-окна, возврат фокуса, отмена при закрытии и отсутствие добавленных аккаунтов. Это не подтверждает полный успешный вход в Minecraft Services.
